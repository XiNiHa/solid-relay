# Querying Data

Solid Relay provides several primitives for fetching GraphQL data in your SolidJS applications. This guide covers the different ways to query data and when to use each approach.

## Basic Queries with createLazyLoadQuery

The most simple way to fetch data is using `createLazyLoadQuery`. This primitive loads data when the component renders and suspends until the data is available.

```tsx
import { Show } from "solid-js";
import { createLazyLoadQuery } from "solid-relay";
import { graphql } from "relay-runtime";
import type { UserQuery } from "./__generated__/UserQuery.graphql.ts";

const UserQuery = graphql`
	query UserQuery($userId: ID!) {
		user(id: $userId) {
			id
			name
			email
			avatar
		}
	}
`;

function UserProfile(props: { userId: string }) {
	const data = createLazyLoadQuery<UserQuery>(UserQuery, { userId: props.userId });

	return (
		// data() is undefined when loading
		<Show when={data()}>
			{(data) => (
				<div>
					<h1>{data().user.name}</h1>
					<p>{data().user.email}</p>
					<img src={data().user.avatar} alt={data().user.name} />
				</div>
			)}
		</Show>
	);
}
```

### Query Variables

Variables can be reactive signals or static values:

```tsx
import { createSignal, For, Loading, Show } from "solid-js";
import { createLazyLoadQuery } from "solid-relay";
import type { UserQuery } from "./__generated__/UserQuery.graphql.ts";

function SearchResults() {
	const [searchTerm, setSearchTerm] = createSignal<string>("");

	const data = createLazyLoadQuery<UserQuery>(
		SearchQuery,
		() => ({ term: searchTerm() }), // Reactive variables
	);

	return (
		<div>
			<input
				value={searchTerm()}
				onInput={(e) => setSearchTerm(e.target.value)}
				placeholder="Search..."
			/>
			<Loading fallback="Loading...">
				<Show when={data()}>
					{(data) => (
						<div>
							<For each={data().search.results}>{(result) => <div>{result.title}</div>}</For>
						</div>
					)}
				</Show>
			</Loading>
		</div>
	);
}
```

### Fetch Policies

Control when and how data is fetched using fetch policies:

```tsx
const data = createLazyLoadQuery(
	UserQuery,
	{ userId: props.userId },
	{
		fetchPolicy: "store-and-network", // Fetch from store first, then network
		// Other options: 'store-only', 'cache-first', 'network-only'
	},
);
```

## Preloading Queries

For better performance, you can consider preloading queries before they're needed.

### Using loadQuery

Preloading page-level queries using the router hook is the recommended pattern of query loading in Relay,
as it allows loading all data required for the page as soon as possible.
While the example shows the pattern applied with Solid Router,
this pattern could be also applied to different router libraries and frameworks, such as TanStack Router.

```tsx
import { query, type RouteDefinition } from "@solidjs/router";
import { Show } from "solid-js";
import { createPreloadedQuery, loadQuery, useRelayEnvironment } from "solid-relay";
import type { UserQuery } from "./__generated__/UserQuery.graphql.ts";

// Example using a Solid Router route preload
export const route = {
	preload() {
		// With this, you can start preloading the query in many cases, including link hovers
		// You can also use route params to set the variables for the preload
		void loadUserQuery("123");
	},
} satisfies RouteDefinition;

const loadUserQuery = query(
	async (userId: string) =>
		loadQuery<UserQuery>(
			// The first call returns the accessor for the environment,
			// and the second call reads the accessor to get the environment
			useRelayEnvironment()(),
			UserQuery,
			{ userId },
		),
	"UserQuery",
);

export default function Page() {
	// The preloaded queries passed into `createPreloadedQuery`
	// get disposed automatically when the user navigates away
	// or the fetch variable changes
	const data = createPreloadedQuery(UserQuery, () => loadUserQuery("123"));

	return (
		<Show when={data()}>
			{(data) => (
				<div>
					<h1>{data().user.name}</h1>
					<p>{data().user.email}</p>
				</div>
			)}
		</Show>
	);
}
```

#### Loading boundaries for preloaded queries

`loadUserQuery` returns a promise, so the preloaded reference is not available on the first render.
While the promise is unresolved, the reads that depend on it are pending, starting with the component that calls `createPreloadedQuery`.
Place a `Loading` boundary around that component, for example in the route layout,
instead of relying only on a boundary inside the component:

```tsx
import { Loading } from "solid-js";

function UserRoute() {
	return (
		<Loading fallback={<div>Loading user...</div>}>
			<Page />
		</Loading>
	);
}
```

### Using createQueryLoader

`createQueryLoader` can be useful if you want to lazily preload additional queries.

```tsx
import { Loading, Show } from "solid-js";
import { createPreloadedQuery, createQueryLoader, type PreloadedQuery } from "solid-relay";
import type { UserQuery } from "./__generated__/UserQuery.graphql.ts";

function App() {
	// The preloaded queries auto-disposes when `App` unmounts
	const [queryRef, loadQuery] = createQueryLoader<UserQuery>(UserQuery);

	const handleLoadUser = (userId: string) => {
		loadQuery({ userId }); // Start loading immediately
	};

	return (
		<div>
			<button onClick={() => handleLoadUser("123")}>Load User</button>
			<Show when={queryRef()}>
				{(queryRef) => (
					<Loading fallback={<div>Loading user...</div>}>
						<UserProfile queryRef={queryRef()} />
					</Loading>
				)}
			</Show>
		</div>
	);
}

function UserProfile(props: { queryRef: PreloadedQuery<UserQuery> }) {
	const data = createPreloadedQuery(UserQuery, () => props.queryRef);

	return (
		<Show when={data()}>
			{(data) => (
				<div>
					<h1>{data().user.name}</h1>
					<p>{data().user.email}</p>
				</div>
			)}
		</Show>
	);
}
```

Place the `Loading` boundary inside `Show`, as above, so the first load shows the fallback. A boundary that is already showing content keeps it while a later `loadQuery` call is pending, and `queryRef()` keeps returning the previous reference until the new query settles. This applies to a boundary placed outside `Show` too, so it would not show the fallback at all.

## Error Handling

Handle query errors with Solid's `Errored` boundary. The fallback receives the error as an accessor and a `reset` function:

```tsx
import { Errored } from "solid-js";

function App() {
	return (
		<Errored
			fallback={(error, reset) => (
				<div>
					<h2>Something went wrong</h2>
					<p>{(error() as Error).message}</p>
					<button onClick={reset}>Try again</button>
				</div>
			)}
		>
			<UserProfile userId="123" />
		</Errored>
	);
}
```

`Errored` also recovers on its own when the inputs of its content change. For example, when a fragment fails because of `@throwOnFieldError` or `@required(action: THROW)` and a later store update makes the data valid, the boundary renders its children again without a call to `reset()`.

### Error Messages During SSR

During server-side rendering, Solid sends `Internal Server Error` to the client in place of the message of any error it serializes, so server details do not leak. To show the original message, mark errors that are safe to expose with `markSafeError`, for example in your fetch function:

```typescript
import { markSafeError } from "@solidjs/web";

const fetchFn: FetchFunction = async (params, variables) => {
	const response = await fetch("/graphql", {
		method: "POST",
		headers: { "Content-Type": "application/json" },
		body: JSON.stringify({ query: params.text, variables }),
	});
	if (!response.ok) throw markSafeError(new Error(`HTTP ${response.status}`));
	return await response.json();
};
```

## Loading States

Use `Loading` to handle loading states:

```tsx
import { Loading } from "solid-js";

function App() {
	return (
		<Loading fallback={<div>Loading user...</div>}>
			<UserProfile userId="123" />
		</Loading>
	);
}
```

The fallback shows only on the first load. When the variables of a query change, a boundary that already shows content keeps the previous data until the new response arrives. `data.pending` is `true` during the first load and during such a refresh, so you can use it to show a refresh indicator:

```tsx
import { Loading, Show } from "solid-js";

function UserView(props: { userId: string }) {
	const data = createLazyLoadQuery<UserQuery>(UserQuery, () => ({ id: props.userId }));

	return (
		<Loading fallback={<div>Loading user...</div>}>
			<Show when={data.pending}>
				<div>Refreshing...</div>
			</Show>
			<h1>{data()?.user?.name}</h1>
		</Loading>
	);
}
```

Reading `data()` outside a `Loading` boundary, such as in an event handler, throws Solid's `NotReadyError` while the query is pending. Read `data.latest` there instead; it returns the current value, or `undefined`, without suspending, and keeps the previous result while a variable change is pending.
