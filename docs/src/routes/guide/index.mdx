# Getting Started

Solid Relay provides SolidJS bindings for Relay, enabling you to use GraphQL with Solid's fine-grained reactivity. This guide will walk you through setting up Solid Relay in different project configurations.

## Prerequisites

Before getting started, make sure you have:

- A GraphQL schema and server
- [Watchman](https://facebook.github.io/watchman/) installed (required for Relay compiler in watch mode)
- Node.js and your preferred package manager (npm, pnpm, or yarn)
- Solid 2.0 (`solid-js` and `@solidjs/web` 2.x)

## Installation

Install the required packages:

```package-install
solid-relay relay-runtime
```

Install development dependencies:

```package-install-dev
relay-compiler @types/relay-runtime vite-plugin-relay-lite vite-plugin-cjs-interop
```

## Project Setup

### Requirements

Solid Relay requires Solid 2.0. Install `solid-js` and `@solidjs/web` 2.x alongside it, and compile with [`@solidjs/vite-plugin`](https://www.npmjs.com/package/@solidjs/vite-plugin).

### Vite

Configure your `vite.config.ts`:

```typescript
import { defineConfig } from "vite";
import solid from "@solidjs/vite-plugin";
import relay from "vite-plugin-relay-lite";
import { cjsInterop } from "vite-plugin-cjs-interop";

export default defineConfig({
	plugins: [
		solid(),
		relay(),
		// required since Relay only gets published in CJS
		cjsInterop({ dependencies: ["relay-runtime"] }),
	],
});
```

### Server-Side Rendering

SolidStart releases target Solid 1, so they cannot run Solid Relay. For streaming SSR, use the start mode of `@solidjs/vite-plugin`, which takes over the role of SolidStart:

```typescript
import { defineConfig } from "vite";
import solid from "@solidjs/vite-plugin";
import relay from "vite-plugin-relay-lite";
import { cjsInterop } from "vite-plugin-cjs-interop";

export default defineConfig({
	plugins: [
		solid({ start: true, ssr: true }),
		relay(),
		// required since Relay only gets published in CJS
		cjsInterop({ dependencies: ["relay-runtime"] }),
	],
});
```

See the [`@solidjs/vite-plugin` documentation](https://www.npmjs.com/package/@solidjs/vite-plugin) for entries, routing, and deployment.

## Relay Configuration

Create a `relay.config.json` file in your project root:

```json
{
	"src": "./src",
	"schema": "./schema.graphql",
	"exclude": ["**/node_modules/**", "**/__generated__/**"],
	"language": "typescript",
	"eagerEsModules": true
}
```

## Setting Up Relay Environment

Create a Relay environment to configure your GraphQL client:

```typescript
// src/RelayEnvironment.ts
import { Environment, type FetchFunction, Network, RecordSource, Store } from "relay-runtime";

// Define your fetch function
const fetchFn: FetchFunction = async (params, variables) => {
	const response = await fetch("/graphql", {
		method: "POST",
		headers: {
			"Content-Type": "application/json",
		},
		body: JSON.stringify({
			query: params.text,
			variables,
		}),
	});

	return await response.json();
};

export function createRelayEnvironment() {
	// Create Relay environment
	return new Environment({
		network: Network.create(fetchFn),
		store: new Store(new RecordSource()),
	});
}
```

## Provider Setup

Wrap your app with the Relay Environment Provider:

```tsx
// src/app.tsx
import { RelayEnvironmentProvider } from "solid-relay";
import { createRelayEnvironment } from "./RelayEnvironment";

function App() {
	const environment = createRelayEnvironment();

	return (
		<RelayEnvironmentProvider environment={environment}>
			{/* Your app components */}
		</RelayEnvironmentProvider>
	);
}

export default App;
```

## Migrating from Solid 1.x

Solid Relay now runs on Solid 2.0. Besides the renamed Solid APIs (`Suspense` is now `Loading`, `ErrorBoundary` is now `Errored`, and `solid-js/web` is now `@solidjs/web`), expect these behavior changes:

- **Reading pending data outside a `Loading` boundary throws.** Calling `data()` from an event handler, a timer, or another untracked scope before the first response throws Solid's `NotReadyError` instead of returning `undefined`. Read `data.latest` to get the current value without suspending. See [Loading States](/guide/querying#loading-states).
- **Changing variables keeps the previous data on screen.** A boundary that already shows content keeps it until the new query settles. `data.latest` keeps the previous result in the meantime, and `data.pending` is `true` until the new result arrives, as in Solid 1.
- **`createQueryLoader` references commit when their query settles.** Place the `Loading` boundary inside the `Show` that checks the reference so the first load shows its fallback. See [Using createQueryLoader](/guide/querying#using-createqueryloader).
- **`Errored` recovers on its own.** When the store data that caused an error becomes valid again, the boundary renders its children again without `reset()`. See [Error Handling](/guide/querying#error-handling).
- **Server errors are sanitized during SSR.** Unless you mark an error with `markSafeError`, the client receives `Internal Server Error` instead of its message.
- **A preloaded query reference from another environment, or one already disposed, reaches the nearest `Errored` boundary** instead of throwing during render.
- **`refetch` holds the cleared load-more flags.** `isLoadingNext` and `isLoadingPrevious` stay `true` until a refetch that cancelled them settles. See [Pagination](/guide/pagination#search-with-pagination).
- **Calling `loadQuery`, `refetch`, or `loadNext` in a component body now fails.** Solid 1 ignored these calls before mount. Solid 2 rejects writes during render in development, so call them from event handlers or effects.

## Important Notes

### Relay Documentation Compatibility

Solid Relay only replaces the React-specific parts of Relay (equivalent to `react-relay`). This means you can use most of the official [Relay documentation](https://relay.dev/docs/) for:

- **Relay Compiler**: Schema definitions, GraphQL syntax, and compilation
- **Relay Runtime**: Store management, network layer, and core concepts
- **GraphQL**: All GraphQL features and best practices

The main difference is in the component-level APIs, which Solid Relay provides as SolidJS primitives instead of React hooks.

### Plugin Choice

This guide uses [`vite-plugin-relay-lite`](https://github.com/cometkim/vite-plugin-relay-lite) instead of `vite-plugin-relay`. The lite version is recommended as it provides:

- Better bundler performance
- Smaller install size
- Better integration with modern build tools
- Automatic codegen with Relay Compiler

If you need additional features not available in the lite version, you can switch to `vite-plugin-relay`, but `vite-plugin-relay-lite` covers most use cases effectively.
